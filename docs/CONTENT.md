## 答案覆盖与出题难度

`content/idioms.seed.json` 是难度配置，每个字配至少 12 个常用答案。它不限制判题范围。

构建阶段生成两种索引：完整合法答案集合与常用答案集合。每回合要求至少剩余 8 个未使用常用答案，优先避开最近三个题面；完整库中的其他收录成语也能答对。常用答案全部耗尽时正常以 `content_exhausted` 结束，不使用生僻答案强行延长对局。

当前 120 条常用配置沿用开发样本，并非语料频率排名；后续需要结合真实试玩校准难度。扩题面时在此文件新增汉字与至少 12 个常用词，并确保每个词都在答案库中。

## 补词、别名与排除

统一修改 `content/idioms.overrides.json`，不要手改生成文件。

- `additions`：上游没有的词条。填写唯一 answerId、text、aliases、initials、tags、source、license、reviewStatus。ID 建议使用 `local-` 前缀；不随排序变化。
- `aliases`：显式认可的其他写法，填写 `{ "text": "标准词", "aliases": ["其他写法"], "reason": "核实依据" }`。别名与标准词共用 ID，防止重复得分。别名冲突会使构建失败；不凭相似程度自动放行。
- `exclude`：排除已确认有误或不适用的记录，填写 `{ "text": "待排除词", "reason": "排除依据" }`。排除规则先于上游和旧样本合并，也不能通过别名绕过。
- `requiredAnswers`：必须保留的词条。目前包含用户反馈的“不拘一格”“水天一色”等，缺失时构建失败。

补词后执行：

```bash
npm run content:build
npm run content:check
npm test
```

普通缺词反馈仍进入 SQLite 供审核，不会在当前对局即时修改词库。人工核实后再写入 overrides。

## 可复现构建与升级

仓库保留原始数据，平时构建不需要联网。`npm run content:fetch` 可重新下载 manifest 固定提交的文件，并在覆盖前验证哈希；该命令不会自动追踪上游最新版本。

`npm run content:build` 将原始数据、旧样本、难度配置、补词规则合并为 `content/idioms.generated.json`。保留原来 120 条词的 ID，新导入词的 ID 根据文本 SHA256 生成。题包版本包含内容指纹，规则或数据变化会生成新版本；相同输入会得到完全相同的输出。

`npm run content:check` 重新计算原始文件哈希，验证生成文件和报告与当前输入一致，并校验题包的独立校验和。构建或启动失败时应修复来源/规则，不能忽略错误继续启动。

更换上游版本时，先更新 manifest 与对应快照，检查新增、移除和疑似错词，再构建、测试。不要覆盖 `idioms.overrides.json`。旧词 ID 不变；难度配置引用不存在的词时会失败，要求明确处理。

服务器每次启动加载固定题包。重建文件不会影响正在进行的对局；更新运行中的题库需要在房间结束后重启服务。每局快照的 `packVersion` 可用于排查问题。

## 客户端数据边界

生成文件位于服务端 `content/`，不在 `public/`。`/api/content` 只返回版本、词条数、题面数和审核状态；房间快照不包含词库或答案集合。生产编译显式复制生成题包到 `dist/content/`，原始解释与例句不进入运行包。
